## 1. 第一版要做到什么

建议做一款中文、2D、故事驱动的 HI 观测解谜游戏。暂称《21厘米：星系来信》，名称仅作为讨论代号。

玩家在射电观测站接到一份待解释的星系观测档案，通过切换观测、调节模型和查看补充证据，逐步看见气体、读出星系运动、追踪气体去向。“来信”是叙事比喻，不表示 HI 信号是天体主动发出的通信。

建议的首版规模为 10–15 分钟、一个主要观测场景、三个递进关卡。核心学习结果是：

1. 不同观测方式提供不同线索，射电能用于研究光学星光未直接呈现的 HI。
2. 观测谱线中包含天体运动的信息，线宽同时受旋转和观察角度等因素影响。
3. 星系外的气体可以留下演化线索，对气体去向的解释需要多项证据，有时还需要补充观测。

v0.1 核心循环：接受任务 → 观察信号 → 拖动或调参 → 比较解释 → 选择证据 → 获得结案反馈。

v0.2 当前修订：自由选对象与选区 → 扫描速度 / 提取孔径谱 / 转动 PV → 记录测量 → 比较结构与运动 → 回访并补充证据。先验证数据工具和探索循环，再扩充叙事、异常结构调查与真实样例。

主流程使用日常语言、动画和图表联动。公式、单位解释与模型假设放进可选的“观测手册”，专业读者可以展开阅读。

建议交付两个入口：网页试玩版用于快速体验，桌面下载版用于离线游玩和课堂展示。两种版本共用关卡、素材与科学模型。

三个主题和画风 B 已经由用户明确选择。名称、时长、角色叙事、详细关卡和技术方案仍为计划建议。当前产品草案见[一页产品说明](PRODUCT_BRIEF.md)。

### 3.2 首版素材清单

| 素材 | 建议数量 | 用途与要求 |
| --- | --- | --- |
| 主观测室背景 | 1 张 | 预留图表与任务区域，不把关键按钮画进背景 |
| 星系档案插画 | 3 张 | 用于档案卡；标注为示意插画，与真实观测区分 |
| 引导角色 | 可选 1 个 | 以头像为主；需要时补充少量表情 |
| UI 组件 | 1 套 | 面板、按钮、标签、图标和状态反馈，可重复使用 |
| 教学示意图 | 约 3 组 | 倾角、旋转方向和补充观测，由代码 / SVG 精确绘制 |
| 结案卡片 | 1 个模板 | 随关卡填写发现、证据和待研究问题 |
| 封面 | 1 张 | 画风确定后制作，用于发布页和宣传 |

工作画布暂按 16:9 设计，概念背景可用 1920×1080；最终导出尺寸按目标设备和体积调整。这是内部工作规格，不是平台强制尺寸。

背景、角色、前景和 UI 尽量分开保存，按钮和角色等需要透明背景的元素独立导出。文字在游戏中排版，方便修改、缩放与后续翻译。

谱线、坐标轴、速度场、倾角示意和科学标签由程序或矢量图制作，确保数据与物理关系正确。美术图负责场景氛围。

素材清单记录文件名、用途、来源、制作工具、可用范围及是否为科学数据。实际素材目录在开始制作时建立。

## 4. 三个关卡的策划草案

| 关卡 | 玩家任务 | 核心操作 | 科学反馈 |
| --- | --- | --- | --- |
| 1 看见隐藏的气体 | 对照同一目标的光学 / HI 视图，标记气体线索 | 切换视图，标记感兴趣的区域 | 不同观测方式提供不同信息 |
| 2 读出星系的运动 | 比较旋转速度与倾角对谱线的影响 | 拖动两个滑块，联动盘示意和谱线 | 不同参数组合可以给出相近线宽，需要明确投影关系 |
| 3 气体去了哪里 | 结合光学图、HI 图与速度线索，追踪候选气体桥或尾 | 整理多项证据，选择支持的解释或补观测 | 星系外气体留下演化线索，但不能凭单一形态唯一确定成因 |

原型中不把“两个模型线宽相近”描绘成“完整谱线必然完全相同”。光学轴比推倾角依赖盘形状等假设，局限在手册和结案反馈中说明。

每关需要写清：任务起点、已知条件、可见数据、操作提示、误判反馈、完成条件、可选手册，以及怎样进入下一关。

以证据与解释作为完成条件。提示可以逐步展开；允许合理回答“当前证据不足”。第一版不设置强制倒计时和失败重开。

在 P2 补齐一页叙事分镜：收到档案 → 用射电看见气体 → 从谱线理解运动 → 追踪气体线索 → 完成档案。剧情长度以不打断操作为准。

## 5. 科学数据与开发方案

### 5.1 科学内容

- 先做可控的合成教学数据，用来验证旋转、投影、速度弥散与仪器效应的表达。
- 单独记录参数、单位、参考系、倾角约定、噪声和近似，不依靠美术外观推导物理量。
- 再选择少量真实案例，保留来源与处理记录。若真实数据准备影响原型进度，可先将其作为可选档案；明确标注已有案例的数据类型。
- 首版包含射电观测、运动和气体演化三个主题，各做一个简化案件。HI 质量定量计算、复杂气体剥离 / 潮汐建模、仪器校准和干涉阵列留给后续章节。
- 由用户完成专业科学审核；代码自检和自动化验证单独记录，不替代专业审核。

科学参考可从 [NRAO《Essential Radio Astronomy》谱线章节](https://www.cv.nrao.edu/~sransom/web/Ch7.html)起步。它介绍 HI 谱线、速度、投影与质量估计的基本关系。

### 5.2 候选工具组合

| 工作 | 建议工具 | 用途 |
| --- | --- | --- |
| 游戏 | Phaser + TypeScript + Vite | 2D 场景、交互、关卡与网页打包 |
| 科学处理 | Python + NumPy + Astropy | 读取数据、生成教学案例、验证模型 |
| 图表 | SVG / Canvas | 动态谱线、标记和盘示意 |
| 美术 | 图像生成工具 / 人工绘图 + 图像编辑器 | 概念图与场景素材 |
| 音频 | 浏览器音频能力、少量离线音效文件 | 点击、操作和发现反馈 |
| 桌面封装（暂停） | Electron + 官方 @electron/packager | 保留后续封装脚本；用户恢复前不执行 |
| 版本管理 | Git | 代码、设计和版本记录 |

当前网页实现采用 Phaser + TypeScript + Vite，教学模型直接用 TypeScript 实现，尚未引入 Python 科研依赖。[Phaser](https://docs.phaser.io/phaser/getting-started/what-is-phaser)以 2D 浏览器游戏为主要方向。

实现时将科学模型、关卡配置、显示界面和平台适配分开，使网页与桌面版本共用游戏内容。Python 的离线处理结果转为 JSON 和图片，玩家无需安装科研处理环境。

## 6. 可下载版本怎么做

后续可沿用网页代码，通过 Electron 封装。已准备官方 @electron/packager 脚本，但用户要求先试玩和修改，当前不继续打包。恢复后仍需验证启动、图表、存档、离线资源与平台运行。[Electron 打包文档](https://www.electronjs.org/docs/latest/tutorial/application-distribution)

| 目标 | 计划中的玩家交付物 | 验证重点 |
| --- | --- | --- |
| 网页 | itch.io 在线试玩 | 资源加载、嵌入窗口、音频开启、浏览器存档 |
| Windows | 完整应用 ZIP，或安装包 | 解压 / 安装、启动、关卡、存档与再次打开 |
| macOS | 包含 `.app` 的 ZIP，或 DMG | 目标架构启动、窗口与字体、存档和分发签名 |
| Linux | 后续根据需求决定 | 在目标发行版实际验证后再承诺支持 |

- Windows 与 macOS 是建议的首批桌面目标，平台优先级与架构范围尚未定案。每个平台在对应环境构建和实际测试；当前没有 Windows 验证环境，后续需要测试设备或构建环境。
- 将数据、字体、图片和音效随包携带，离线完成核心游戏。测试时实际断网，从启动到结案完整走一遍。
- 玩家只需运行所下载的游戏，不需要安装 Node.js、Python 或启动开发服务器。以成品在干净环境中的运行结果验收。
- 普通网页资源 ZIP 与玩家桌面包分开命名。网页资源包用于部署，不能默认双击 `index.html` 就可正常游玩。
- 为公开桌面分发安排代码签名、macOS 公证等平台流程，具体根据目标平台和发布方式确定；在计划中预留时间与可能的费用。
- 游戏进度保存在用户数据目录，避免写入安装目录；网页存档与桌面存档不默认互通。
- 第一版手动下载更新即可；版本说明交代进度兼容性，不引入自动更新服务。

如果桌面包体积成为关键限制，再单独评估 Tauri；它有 Rust 和平台开发环境要求，切换前应验证 WebView 中的渲染与行为一致性。[Tauri 环境说明](https://v2.tauri.app/start/prerequisites/)

## 7. 测试与阶段验收

P3 完成单关后先找少量目标玩家观察操作，问题解决后再投入完整素材。P5 计划邀请 6–10 名目标玩家试玩，包含高中 / 大学生与非专业大众，另安排专业科学审核。

记录玩家在哪一步停住、依赖什么提示、为什么选择某项证据，以及玩完后能否解释一个未见过的新案例。人数和结果仅用于早期迭代，不直接据此宣称已证明教学有效。

建议验收目标：

- 玩家开始后约一分钟内能进行第一项有效操作。
- 多数试玩者在无需现场口头指导的情况下完成主要流程；游戏内提示可以使用。
- 新案例检查覆盖：光学 / HI 观测信息的差别、线宽与倾角关系、气体去向的证据与有用的补充观测。
- 科学审核无未处理的重大错误；文字、单位与图表一致。
- 在当前稳定版 Chrome / Edge、Firefox 和 macOS Safari 检查核心流程，并记录实际覆盖的平台和版本。
- 桌面包在每个声称支持的平台进行启动、断网游玩、关闭重开与存档验证。没有测试的平台明确标为未验证。
- 在 1366×768 等常见桌面窗口检查文字和拖动区域。关键线索不只依赖颜色，音频可关闭。

若试玩者不理解核心操作，优先修改引导、反馈或谜题结构，修改后再检查相关流程。

## 8. 在哪里发布

### 8.1 首发：itch.io

建议在一个游戏项目中组织网页试玩与桌面下载，先小范围测试，再公开首版。itch.io 支持 HTML 游戏，并提供 Restricted 等访问控制；测试阶段按实际需要设置访问范围。[HTML5 发布说明](https://itch.io/docs/creators/html5)、[访问控制说明](https://itch.io/docs/creators/access-control)

网页部署包包含 `index.html` 和所需资源，使用正确的相对路径。桌面下载按操作系统、架构和版本分别标注，避免玩家误下开发源代码。

发布页准备：游戏简介、受众、预计体验时长、操作方式、可玩平台、封面、约 3–5 张实际截图、版本说明、数据与素材署名、反馈入口。可追加一段 30–60 秒实机录屏；不依靠概念图代替实际画面。

建议首版免费开放体验。付费模式和正式商业化后续再决定。

## 9. 初步排期与分工

以 6–8 个工作周作为初步规划窗口，不绑定日历发布日期。估算依据是一个主要场景、三关、少量原创素材和两类分发方式；实际投入时间、修改轮次、科学数据与跨平台测试条件会影响进度，单关原型完成后重新估算。

| 工作周 | 重点 | 可审阅结果 |
| --- | --- | --- |
| 第 1 周 | 一页定位、三张概念图、界面草图与关卡策划 | 看懂整体气质和玩家任务 |
| 第 2–3 周 | 科学模型和单关交互原型，进行早期试玩 | 可以完整玩一次核心谜题 |

第 3 周的内容可按原型进展调整，不要求两阶段机械串行。没有完成验证的桌面平台可以晚于已验证的平台发布，并明确说明支持范围。

| 责任 | 用户 | Codex |
