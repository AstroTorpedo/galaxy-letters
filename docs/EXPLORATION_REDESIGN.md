# 从选择题流程转向数据探索

日期：2026-10-14。起因：用户认为 v0.1 的数据与画面不够逼真、探索性不足，希望使用真实观测或模拟 cube，并重新参考 Star Beat。

## 当前版本的实质问题

1. 图像、速度场和全局谱线分别生成，没有共同的三维数据作为基础。
2. 固定 A/B/C 候选区域预先指出线索，玩家主要完成指定点击和选择解释。
3. 每个主题只有一个教学步骤，目标少，完成后没有继续观察的空间。

## 参考游戏的已确认信息

Star Beat 的作者说明明确介绍：真实 Kepler 数据、频率与恒星识别、理论阅读与实践任务、允许试错，以及解锁后展示图像与振荡声化的房间。出处：[设计者说明](https://ananunez.carrd.co/)、[游戏页](https://bruja-aprendiza.itch.io/star-beat)。

这给本项目的启发是：环境中的阅读工具、可操作的信号测量、收集后可继续欣赏的天体档案，应当形成一个循环。不是简单增加更多解释卡。

公开构建的静态文字还确认了两类具体练习：在时域 / 频谱联动工具中调整幅度和频率；从频率峰序列中寻找径向模与频率间隔。还包含物品拾取说明。这启发我们把可操作的信号工具、观测手记 / 图鉴与可回访的探索作为当前循环。静态文字并不证明已体验到所有实际关卡或完整流程。

本轮网页试玩加载仍受阻，不能声称已通关。只使用页面、作者说明和公开构建中的静态内容核实信息；不会把参考游戏的专有图片、声音或代码加入本项目。

## 新的数据方向

- 实测：THINGS 的 DDO 154 自然加权 HI cube。已读取 FITS 头：1024×1024×57，原单位 Jy/beam，原谱轴标识 FELO-HEL。需按 WCS 处理速度轴，并记录重采样。
- 光学：使用官方 Legacy Surveys FITS cutout 服务获取同一目标与覆盖范围，按 WCS 对齐，而非仅把两张不同视场的图片放在一起。
- 模拟：生成带旋转、速度弥散、有限波束、谱分辨率与相关噪声的 position–position–velocity cube；保留无噪声模型以验证处理和设计任务。
- 实测与模拟分开标注。模拟并不声称是完整流体动力学演化计算。
- 所有 channel map、moment map、局部谱线、全局谱线和 PV 图都从同一份 cube 派生。
- cube 的第三轴是速度 / 频率，不是第三个空间深度。

官方数据入口：[THINGS 数据页](https://things.www3.mpia.de//Data.html)、[Legacy Surveys cutout 文档](https://www.legacysurvey.org/viewer/urls)。此前已验证 FITS 头与服务入口；用户随后提出自行模拟及 M33，真实下载已停止，部分文件保留于忽略目录，未作为可玩对象。两套模拟数据已接入 `/explore.html`。M33 所在硬盘掉线，等恢复后再处理。

## 新的核心操作

1. 自由移动选区，在任意位置提取谱线，不预先圈出答案。
2. 调节速度通道并播放扫描，观察发射随速度变化。
3. 调节显示拉伸与阈值，比较弱信号和噪声；明确区分显示操作与数据改变。
4. 在积分图、速度图与光学图之间对照，按需要保留测量。
5. 选择孔径和切线方向，查看局部谱线或 PV 结构。
6. 将有用的区域、频段与测量结果保存为玩家自己的发现记录。

## 内容与反馈

- 保留用户选定的暖色观测室 B，增加可自由打开的观测终端、资料书和星系档案。
- 当前提供两个不同物理结构的模拟对象；实测星系为后续对照计划，尚未接入。
- 任务使用测量和证据达成条件，例如检测信号、测出两侧不同速度、验证弱结构跨多个通道存在；不要求猜预设热点。
- 主线仍覆盖射电观测、星系旋转、气体演化；自由探索中允许随时换对象、回看和补充测量。
- 收集后的档案展示真实数据来源、玩家的截图 / 测量和可选的数据声化，清楚说明声化是映射后的音频。
